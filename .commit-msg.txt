Make the adaptive loop actually run, and stop it claiming things it did not earn

A review of the learner model and the storage around it found that the
recovery loop — baseline → intervention → transfer → delayed retest — could
not run for the ordinary case, that several "you have demonstrated this"
claims did not require the learner to have demonstrated anything, and that one
stored value could leave the device in cleartext.

## The loop never started

`learnerErrorStore` chose the evidence lane for each success from
`evidenceStrength`, which measures from the entry's FIRST mistake. That
timestamp never moves — `recordLearnerSuccess` deliberately leaves it alone,
because it is what the weakness record is for. So once a weakness was older
than the 20-hour delay floor, *every* later success was filed as `delayed`, and
the intervention and transfer lanes stayed empty permanently.

This is not cosmetic. `dueLearningChecks` returns nothing for a cycle with no
intervention, and `learningCycleStatus` reaches DEMONSTRATED only with an
independent transfer AND an independent delayed pass. A weakness the learner
returned to the next day — which is nearly all of them — therefore reported
"needs confirmation" forever while owing the learner nothing at all.

Lanes are now positional: the first one the cycle has not yet satisfied. An
explicit `delayed: true` from a caller still wins, because the scheduled-retest
path checks the clock itself. A verified transfer still claims the transfer
lane. A *supported* pass taken at the transfer check is filed as practice,
because the follow-up UI allows revealing the transcript and still passing.

## Assisted answers no longer prove unaided ability

Four places treated a clock fact as a fact about the learner:

- `dueLearningChecks` settled the delayed debt on any `correct === true` row,
  so a scaffolded pass cancelled the one check that would have demonstrated
  unaided recall — while `learningCycleStatus` still required an independent
  one. The learner got "nothing owed" and "not demonstrated" simultaneously,
  and was never asked again. The delayed step now requires an independent pass,
  the same standard the status uses.
- `capabilityModel` promoted a capability to `demonstrated` on "this cycle has
  a transfer row and a delayed row", ignoring independence — so a cycle whose
  delayed pass was assisted rendered "You have used this on your own — in new
  situations and later on." It now defers to `learningCycleStatus`.
- `weaknessLifecycle` and `progressEvidence` read `lastEvidence === 'delayed'`,
  which `evidenceStrength` sets from the clock alone, and told the learner they
  had used something "later, with no help". Both now check independence, the
  way their sibling filters already did.

## Storage

- `exportProgress` was copying `fp.learner.<memberId>.fp.groqKey` into the sync
  code and the `/api/sync` push. The filter was already there and still missed
  every time: `[^]+` is greedy, so it read the member id as `m-x1y2.fp` and the
  key being tested as `groqKey`. Now `[^.]+`, which is exact.
- `writeRaw` only retried after a prune attempt that found a log long enough to
  halve. With short logs it fell out having written nothing and reported
  nothing, so a completed conversation could vanish silently. The retry now
  runs after every attempt, and `write` returns whether the value landed.
- `claimLegacyFor` recorded the claim even when the copy threw, permanently
  orphaning pre-household data — reads returned empty and the next save
  overwrote it with `[]`.
- `learnerRead`'s new legacy fallback is gated on the claim belonging to this
  member, so it cannot leak one member's data to another.
- `importProgress` rejects null and wrong-typed values (`hasExpectedShape`).
- `sessionHistory` is capped at 500 instead of being fully rewritten per save.

## The planner was measuring things it never recorded

- `plannerState` read `durationSeconds` and `kind === 'speaking'`, neither of
  which `saveSession` writes, so every session fell through to a turn count:
  60 turns with long pauses scored ~36 minutes against a 20-minute speaking
  floor. It now reads `speakingSeconds`, still falling back to turns for
  history written before that existed.
- `listeningMinutes7d` was `totalMinutes * 0.2` — a fabricated number that
  put heavy users over the "listening starved" threshold, so a learner who had
  done no listening was never scheduled any. Listening records no duration
  anywhere in the app, so it now reports 0.
- `recentMinutes` sliced the window start in UTC; a 21:30 session in New York
  landed on the wrong day. Local, like every other "Today" surface.

## React lifecycle

- `TranslateDrill` froze an empty pool for DE/ES (sync facade, returns `[]`
  before the registry resolves) and then indexed into it, throwing into the root
  ErrorBoundary. Now uses the async door, with a loading and an honest empty
  state, and draws from free indices instead of resampling forever.
- `useRecorder` left the microphone open when the permission prompt outlived
  the screen, and releasing the stream fired `onstop` — which billed a full
  transcription for audio the learner never submitted. Both fixed.
- `useSessionLifecycle` wrote the previous member's transcript into the new
  member's namespace on a household switch.
- `ChatArena` kept answering after unmount, appending to history and awarding XP.
- `Reading` had no request sequencing: a slow lookup for word A overwrote the
  popover after the learner had tapped B.
- `PhraseDrills` rebuilt its queue when `starred` changed, shifting every index
  mid-run — starring a phrase skipped a card and repeated another.
- `ExamSimulator` banked a push-to-talk burst twice (mouseup, then mouseleave).
- `Writing` applied a verdict and awarded XP after unmount.
- `App`'s async level-up overwrote any setting changed while the chunk loaded.

## Content

French had 130 head-words duplicated across themed packs — 143 redundant SRS
cards, 60 with conflicting glosses (`enfin` as "well / I mean" and "finally /
at last"). The frequency layer now drops cards the themed packs already teach:
3,020 → 2,637 entries, with ids unchanged so no review history is merged.
`LEADING_ARTICLE.fr` now strips definite articles only; including `un|une|des`
would have removed the first word of phrases like "un peu".

## Also

`mistakeGraph` documents a −20 penalty for wrong answers that no code path can
reach, because `classifyRetest` folds every wrong answer into REHEARSAL. The
comment now describes what actually happens.

15 new regression tests in `tests/review-fixes.test.js`, one per defect, each
naming the learner-visible behaviour that was wrong.

1176 tests, all three lint gates, and every build budget green.
